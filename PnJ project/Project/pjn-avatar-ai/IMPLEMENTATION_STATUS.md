# PnJ 구현·검증 기록

## 2026-11-25 · 팀원 공유용 외부 HTTPS 데모

- **실행과 종료.** 루트의 `share_start.bat`은 링크를 표시·복사하고 기본 브라우저를 연다. `share_stop.bat`은 공유 프로세스만 종료한다. 현재 주소는 `.runtime/share/url.txt`에 있다. 사용자가 선택한 방식은 이메일 제한이 없는 공개 링크다. 호스트와 인터넷·터널이 동작해야 하며 재시작 시 주소가 바뀐다.
- **분리.** 새 `share.ps1`이 전용 빌드와 프로세스 소유권을 관리하고 새 `backend/app/share.py`가 정적 화면과 API를 함께 제공한다. 터널이 Host를 공유 서버의 루프백 주소로 설정하며 허용 호스트는 127.0.0.1이다. 공유 DB는 `.runtime/share/demo.sqlite3`다. 세션 쿠키는 Secure, HttpOnly, SameSite=Strict, Path=/api다.
- **수정.** `backend/app/accounts.py`의 공유 쿠키, `travel.py`의 직접 AI 요청 거절, `llm.py`의 공유 시 dotenv 및 클라이언트 차단, `frontend/src/App.jsx`와 `Travel.jsx`의 가상 정보 안내와 Demo 전용 선택, README를 수정했다. 기존 start.bat, stop.bat, 관광지·사진·아바타·설문은 보존했다. 프로젝트 전용 cloudflared는 공식 2026.11.2 Windows x64 바이너리를 SHA-256 대조 후 설치했다.
- **실제 브라우저.** Cloudflare HTTPS 주소에서 PC 1280×900은 미호, 모바일 390×844는 민으로 각각 가입·20문항·로그인을 완료했다. 같은 기분에 서로 다른 공감, 같은 자연 여행 희망에 푸른수목원·보라매공원·선유도공원, 각 사진의 로딩 너비 960px을 확인했다. 두 화면 모두 P·반반·J 전환 시 코스 ID와 DAY 1~2 순서가 같았다. 좋아요, 거절 이유와 대안 추천, 마이페이지 동반자 변경, 로그아웃·재로그인 후 유지도 확인했다. 증빙은 `.runtime/share/desktop.jpg`, `mobile.jpg`다. 실물 휴대전화와 별도 이동통신망은 미검증이다.
- **보호 검증.** 인증된 외부 요청에서 AI 기분·코스·기존 추천 API 모두 HTTP 403 DEMO_ONLY였다. 실제 OpenAI 호출은 0회다. 새 회원의 기록은 비어 있었고 타 회원 코스 피드백은 404였다. 설정·DB·로그와 API 문서 경로는 404, 로그아웃 후 회원 API는 401이었다. .env와 .gitignore 해시는 작업 전후 동일했다.
- **실사용 DB.** 전체 작업 구간의 DB 파일 해시는 달라졌다. 기존 개발 서버 로그에 피드백 저장이 있으며 실사용 DB의 피드백 갱신 시각(16:01:39 KST)은 파일 수정 시각과 일치했다. 공유 DB 최초 생성은 16:02:20 KST다. 실사용 DB 내 이번 검증 계정 0개, SQLite 무결성 검사 정상이다. 마지막 두 서버 상태 점검 구간에는 실사용 DB 해시가 동일했다. 기존 회원의 로컬 사용 기록은 그대로 유지했다.
- **실행기 검증.** 첫 공유 서버를 종료한 뒤 로컬 개발 서버의 정상 응답을 확인했다. 포트 충돌 시 시작 실패와 원인 표시, 최종 터널에서 중복 시작 시 같은 두 PID와 URL 유지, 클립보드 일치를 확인했다. 기존 자동 테스트 34개가 통과했다. 공유 프로세스를 실행 상태로 두었다.

## 2026-11-25 · 동반자 상담, 설문 강도와 회원별 기억

- Demo에서 미호와 민은 기분 단서에 맞는 서로 다른 한국어·영어 공감 문구와 여행 제안 표현을 사용한다. 화자 설정은 backend/app/personas.py와 frontend/src/avatarConfig.js에서 관리한다. 대기·듣기·준비·응답 상태를 기존 아바타 옆에 표시한다. 실제 OpenAI 호출은 0회였다.
- 설문 강도는 기존 버전의 유효한 원응답에서 요청 시 계산한다. 각 영역의 선택 횟수 0~4를 표시하며 동률을 균형형으로 안내한다. 원응답이 없으면 대표 태그만 사용한다. 동행 한 문항만 바꾼 통제 실험에서 대표 태그가 같은 4:0과 3:1 회원의 중립 입력 1위가 푸른수목원(설문 일치 16표)에서 보라매공원(17표)으로 달라졌다. 임상검사 수치·확률이 아니다.
- 선택한 코스 상세에서 좋아요, 선택형 이유를 포함한 거절과 대안 요청, 직접 방문 및 선택 만족도(1~5)를 별도로 저장한다. 기존 SQLite trips.result에 feedback을 추가하는 방식으로, 회원이 행동할 때 해당 추천 행만 갱신한다. 쓰기 트랜잭션에서 소유 회원과 실제 추천 코스 ID를 확인한다. 좋아요·거절만으로 방문을 기록하지 않는다.
- 서버가 피해야 할 조건을 먼저 적용하고 희망·숙소 권역·현재 기분 적합도를 우선 비교한다. 그 다음 설문 일치 표수에 동일 장소·공통 경험 태그·거절 이유·명시한 방문 평가의 보조 점수(합계 −5~+5)를 반영한다. 장소별 최신 의사표시와 방문 평가는 독립적으로 불러온다. 최근 추천 이력은 동점에서 다양성을 고려할 때 쓴다. 대안 요청은 방금 거절한 장소를 제외하며 세 곳 미만이면 확인 질문을 보여준다.

## 11월 25일 사용자 제보 재검증

- **재현 조건** — 작업 시작 시 PID 기록은 비어 있었고 8000·5173 모두 리스너가 없었다. 수정 전 배치를 켰을 때는 두 호스트명 모두 원본 PNG와 채점 POST가 200이었다. 기존 가입폼을 브라우저에 연 채 서버를 종료하자 소개·검사 중 이미지의 자연 크기가 0×0이 됐다. 브라우저는 메모리에 있는 문항을 끝까지 표시했지만, 20번 제출 시 제보와 동일한 연결 오류 문구를 표시했다. 사용자 최초 실패 시각의 POST/상태 코드는 남아 있지 않아 그때 서버가 멈춘 경위까지 확정할 수 없다.
- **호출과 오류 처리** — 브라우저는 동일 출처의 `POST /api/survey/score`로 `{version, answers}`를 보낸다. 답변은 `s1`~`s20`을 키로 하는 0부터 시작하는 정수 선택지다. 기본 Vite 포트는 5173, 프록시 대상은 127.0.0.1:8000이다. 기존 클라이언트는 fetch 실패와 JSON 오류 코드가 없는 HTTP 실패에 같은 문구를 사용했다. 이제 요청 경로·메서드, HTTP 상태 또는 응답 부재, 복구 방법을 표시한다. 배치는 빌드한 앱을 Vite preview로 제공해 개발용 자동 새로고침 없이 기존 탭에서 재시도할 수 있다. 시작 시 브라우저와 같은 경로로 저장 없는 채점 POST도 확인한다.
- **이미지와 문구** — 확인한 원본 `frontend/src/images/Avatar_Miho.png`를 그대로 `frontend/public/images/Avatar_Miho.png`에 복사했다. 원본과 SHA-256이 일치한다. 고정 정적 URL로 페이지 시작 시 미리 로드한다. 예전 Codex 경로 참조는 해당 코드에 없었다. 문항과 선택지를 한·영으로 모두 검수했고 2번은 요청 문장을 적용했다. `pnj-travel-1`의 문항 ID·선택지 순서·채점 태그를 유지했다.
- **브라우저 실측** — 기본 start.bat 주소에서 가입 정보를 입력하고 소개 3문장, 우측 상단 미호, 실제 20개 선택, 완료 2문장, 회원가입 계속, 수동 로그인, 메인 화면을 조작했다. 네 화면 모두 디코딩된 원본 1086×1448과 화면 캡처로 표시를 확인했다. 소개 화면 99프레임에서 양쪽 눈꺼풀 불투명도는 0~0.996, 대기 이동은 약 0~1.5px였다. 미소는 원본 표정이다. 캡처는 `.runtime/repair-intro.jpg`, `repair-survey.jpg`, `repair-complete.jpg`, `repair-main.jpg`에 있다.
- **실패 복구 실측** — 수정 후 마지막 답까지 선택한 상태에서 검증 백엔드만 정지했다. 브라우저에 POST 경로와 HTTP 502가 표시됐고 프록시 로그에도 `ECONNREFUSED 127.0.0.1:8000`이 기록됐다. start.bat이 기존 프런트엔드를 재사용해 백엔드를 복구했다. 같은 탭에서 입력·재검사 없이 검사 완료를 다시 눌러 200을 받았고 기존 비밀번호로 최종 가입(201), 로그인(200), 검사 결과·INFP 확인, 프로필 수정·저장(200)까지 진행했다.
- **데모 회귀 확인** — 검증 프로세스에서만 dotenv 로딩과 키를 끈 상태에서 기분 입력 후 카드 0개, 희망 제출 후 카드 3개를 확인했다. 선택한 정원 코스 3지점은 P·반반·J 모두 같았고, J에는 체류 시간 예시가 표시됐다. localhost·127.0.0.1의 프록시 채점과 이미지 요청 모두 200, 서버 테스트 5개 통과. 실제 OpenAI 요청은 이번 점검 대상에서 제외했다.
- **실행 환경** — 검증 계정은 별도 `.runtime/repair-qa.sqlite3`에 생성했다. 기존 사용자 데이터, `backend/.env`, `.gitignore`는 수정하지 않았다. 검증 종료 후 일반 설정으로 실행해 둔 앱은 http://127.0.0.1:5173/ 에서 사용할 수 있다.

## 시연 가능한 범위

비로그인 첫 화면 → 기본정보 → 미호 소개 3문장 → 여행 개인화용 자체 심리 테스트 20문항 → 완료 2문장 → 회원가입 계속 → 최종 가입 → 직접 로그인 → 기분에 공감 → 여행 희망 → Top 3 → 선택한 코스의 P·반반·J 보기. Demo Mode에서는 외부 모델을 호출하지 않는다. KO/EN UI와 두 언어의 문항·데모 콘텐츠가 있다. 저장된 대화와 추천은 생성 언어를 유지한다.

실사용 계정 DB는 첫 사용 시 `backend/data/pnj.sqlite3`에 생성한다. 이번 시연 계정은 별도 `.runtime/flow-qa-20261125.sqlite3`에만 저장했다. 이전 브라우저 기록은 원래 로컬 키에 남는다. 기존 코드·설정·배치의 실행 경로에서 예전 폴더명을 참조하는 부분은 발견되지 않았다.

## 남은 확인과 다음 시작점

- 구현 중인 필수 화면은 없다. 외부 연동의 성공 검증이 남아 있다. OpenAI 사용 한도·호출 제한 상태를 확인한 뒤 메인에서 OpenAI를 선택하고 예시 기분과 희망을 순서대로 제출한다. `POST /api/travel/mood`, `POST /api/travel/courses` 모두 성공하고 결과 mode가 ai인지 확인한다. 공급자 코드는 `backend/app/travel.py`의 ai_output이다.
- 데모는 한정된 여행 콘셉트와 표현 사전을 사용한다. 추가 표현·복합 제약 사례는 `backend/app/catalog.py`와 `backend/tests/test_journey.py`에서 확장한다. 실제 시설의 접근성·주차·비용은 확인할 수 없다.
- 실물 모바일 기기에서 눈꺼풀 합성·화면 전환 외관을 확인하고 싶다면 `frontend/src/Miho.jsx`와 `journey.css`가 시작점이다. 음성·립싱크·3D 리깅은 이번 범위 밖이다.

## 실행

프로젝트 루트에서 `start.bat` 실행 → http://127.0.0.1:5173/ → 회원가입부터 시연. 종료는 `stop.bat`. 기본 포트를 사용할 수 없으면 `start.bat 8014 5175`와 http://127.0.0.1:5175/ 를 사용한다. 로그는 `.runtime`에 남는다.
