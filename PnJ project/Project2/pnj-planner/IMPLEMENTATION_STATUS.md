# PnJ 플래너 구현 및 검증 기록

## 현재 버전 · 근거 추적형 추천 2.1

- 기분 한 문장이나 생략으로 Top 3를 받는 흐름, 회원·설문·사진·코스 상세를 유지했다. 24문항의 영어 원문·특성·부호를 공식 IPIP 키와 대조했다. 12개 특성 중 6개만 약한 추천 신호로 쓴다.
- 최종 2025년 조사 6,067명과 통합본 2,423명을 분리했다. 후자의 2,423개 ID와 세 활동 표시가 모두 최종본에도 일치한다. 5개 집단 × 활동·장소 14개를 공식 표와 대조한 뒤 활동 집계만 마지막 동률 판단에 연결했다.
- 기분 자동 재사용 경로, 부정 표현, 같은 활동 단서의 중복 가산, 비교 단위가 다른 비용을 수정했다. 인계 파일에 검사 스냅샷·답변 기준 시각·수정된 경험·P/PnJ/J 상세도를 포함한다.
- `start.bat`을 `.runtime/qa-evidence-2025.sqlite3`로 실행했다. Chrome 1360×900·390×844에서 가입 24문항, 복원·재시도, 재로그인, 조건 없는 추천, 한영 복합 표현 네 가지, 생략·재사용·수정, 예산 미확인, 실내 필수·회피, 고정 일정, 사진 디코딩, 한국어·영어 보기와 미아 JSON 다운로드를 확인했다. 과거 20문항 계정의 당시 점수 인계와 재검사도 통과했다.
- 백엔드 39개와 프런트엔드 3개 테스트가 통과했다. FastAPI 테스트 클라이언트의 기존 HTTPX 경고 1건이 있다. 브라우저 외부 요청과 미처리 페이지 오류는 0건이었고 PnJ의 실제 OpenAI 호출은 0회였다.
- 원본 실사용 DB·설정·사진은 유지했다. Project 앱과 공유 터널은 조작하지 않았다. 실제 미아 전송·실시간 외부 피드·실사용 만족도·한국어 단축 설문의 심리측정 타당성은 미검증이다.
- QA 종료 후 기본 `.runtime/planner.sqlite3`로 다시 실행했다. 상태 API에서 `ok`, `verified_historical_aggregate`와 24문항을 확인했다. 작업 전후 기본 DB 파일과 `.env.example`의 SHA-256이 일치했다.
- 다음 작업은 `ALGORITHM_EVIDENCE.md`의 통제 프로필로 서울 방문 예정자에게 후보를 비교 제시하고 실제 선택에 따라 `ranking_rules.json`과 `survey_stats.EXPERIENCE`를 검토하는 것이다. 신규 공급자는 `sources.applicable`의 출처와 유효기간 계약에서 시작한다. [집계 전처리와 원자료](DATA_SOURCES.md) · [계산 예시](ALGORITHM_EVIDENCE.md)

### 직접 검증한 항목

- Windows의 실제 `start.bat`과 전용 `.runtime/qa-mood-flow.sqlite3`에서 설치된 Chrome으로 실행했습니다. 1360×900과 390×844 화면을 검사했습니다. 대표·상세 관광 사진의 실제 디코딩과 가로 넘침도 확인했습니다.
- 가입 24문항 전체에서 ID, 한영 문항, 상단 번호, 완료율을 대조했습니다. 이전·다음·새로고침·한영 전환·번역 유사 DOM 변경 후에도 번호가 맞았습니다. 마지막 미응답은 완료할 수 없으며, 가입 요청 실패 후 기존 입력으로 재시도했습니다.
- 같은 새 회원이 칩을 고르지 않고 “오늘 너무 지쳤어. 그냥 편하게 쉬고 싶어.”라고 썼을 때 서울식물원·선유도공원·반포한강공원이, “기분 좋아서 서울에서 재밌는 걸 하고 싶어.”라고 썼을 때 북서울미술관·덕수궁·광장시장이 제시됐습니다. 저장된 성향과 실제 이력에 따라 순위가 달라질 수 있습니다.
- 모호한 입력, 기분 생략, 지난 답 재사용, 결과에서 기분 해석 수정, 예산만 입력한 경우를 검사했습니다. 미정 날짜·기간·숙소를 지어내지 않았습니다. 실내 필수와 회피 장소, 4박 5일 예시의 기존 약속을 보존했습니다.
- P·PnJ·J 및 한영 전환에서 선택 ID와 장소 순서가 유지됐습니다. JSON 다운로드 결과를 미리보기와 대조했고, 해석한 기분·선택 이유·미확인 조건을 확인했습니다. 선택·거절·방문 기록과 재로그인 뒤 직접 선호도 검증했습니다.
- 별도 QA DB에 종전 형식 회원을 만들어 재검사 없이 추천을 받았습니다. 마이페이지 5개 영역 → 자발적 24문항 갱신 → 12개 영역 표시를 확인했습니다. 원래 20개 응답, 직접 입력한 선호, 기존 추천 노출은 유지됐습니다.
- 백엔드 회귀 테스트 29개, 프런트엔드 테스트 3개가 통과했습니다. 테스트 클라이언트의 HTTPX 사용 중단 예정 경고 1건이 있습니다. 실제 OpenAI 호출은 0회였습니다. 증거 화면은 `.runtime/qa-mood-first-desktop.png`, `.runtime/qa-mood-first-mobile.png`에 있습니다.

기본 DB로 다시 시작한 뒤 상태 API에서 `offline_rules`, 검사 버전 `pnj-facets-24-v1`, 문항 24개를 확인했습니다. 작업 전후 원래 플래너 DB의 기존 테이블 내용, 설정 예시, 서울 사진 30개, 기존 Project 앱의 실사용 DB와 환경 파일을 지문으로 대조해 모두 일치했습니다. 플래너 DB에는 과거 검사와 확인 조건을 보관할 테이블만 추가했습니다. 기존 Project 앱과 공유 터널은 조작하지 않았습니다.

**자동 테스트**는 독립 임시 SQLite에서 백엔드 26개, 프런트엔드 Node 테스트 3개가 통과했습니다. 백엔드 통합 테스트는 가상 키를 설정하고 외부 소켓 연결을 금지한 채 전체 추천을 실행합니다. 설치된 FastAPI의 테스트 클라이언트가 HTTPX에 대해 사용 중단 예정 경고 1개를 냅니다.

**실제 브라우저**는 전용 `.runtime/qa-browser.sqlite3`로 실행한 `start.bat`과 로컬 Chrome 158을 사용했습니다. 1360×900과 390×844에서 가로 넘침이 없었습니다. 7번 문항 새로고침, 첫 가입 요청 실패 후 응답 보존·재시도, 로그인, 기분/희망 입력, 초안 3개, 개별 코스 상세, 피드백·방문 기록, 다운로드까지 확인했습니다. 대표 사진 3장과 선택 코스의 상세 사진 4장이 실제로 디코딩됐습니다. 브라우저 외부 요청 0건, 미처리 페이지 오류 0건이었습니다. 화면 증거는 `.runtime/qa-desktop-results.png`와 `.runtime/qa-mobile-results.png`에 있습니다.

**추천 비교**에서 동일 프로필로 휴식과 조용한 분위기를 골랐을 때 보라매공원·서울식물원·북서울꿈의숲, 새로운 경험과 높은 활동량을 골랐을 때 덕수궁·광장시장·인사동길이 선택됐습니다. 사용자 직접 선호가 있으면 같은 축의 임시 추정을 대체합니다. 실험은 규칙이 의도대로 작동하는지 확인한 것으로, 실제 여행자 만족도는 아직 측정하지 않았습니다.

**기존 프로젝트 보호**를 위해 기존 앱은 읽기 전용으로 조사했습니다. 작업 전후 기존 `backend/.env`, `backend/data/pnj.sqlite3`, `.gitignore`, `start.bat`, `stop.bat`의 SHA-256이 일치했습니다. 개발 서버·공유 터널은 조작하지 않았습니다. 이번 작업의 PnJ 실제 OpenAI 호출은 0회입니다.

## 범위 밖과 다음 시작점

- **시간·이동·식사·비용** — 실제 경로, 교통 소요 시간, 식당 메뉴와 알레르기 교차접촉, 전체 비용은 미검증입니다. 다음 작업은 `data/places.json`의 출처별 운영·요금 범위를 확장하고 `schedule.verify_limits`에 검증된 이동 구간을 넣는 것입니다. 약속 전후 이동을 입증하기 어려운 날은 보수적으로 비웁니다.
- **품질 평가** — `ranking_rules.json`의 가설 가중치를 서울 방문 예정 여행자의 비교 선택으로 평가해야 합니다. 한국어 번역 검토와 여행 선호 매핑의 타당성 평가도 남았습니다.
- **정보 공급자** — `trip.weather_snapshot`에 실제 날짜별 예보 공급자를 연결할 수 있습니다. `sources.py`의 조사·트렌드 공급자는 비활성입니다. 조사 활용에는 문항 정의·WT가 있는 원자료 또는 출처가 확인된 가중 집계가 필요합니다.
- **미아·LLM** — `schedule.handoff`의 `mia.itinerary/1` 필드를 미아 팀과 합의한 뒤 별도 수신기로 연결합니다. LLM을 검토할 때는 `plans_api.recommend`의 규칙 계산 경계를 이용하고, 먼저 실제 호출 비용·전송 필드와 평가 기준을 정해야 합니다.
- 실기기 휴대폰 실측, 상용 배포, 공모전 코드·사진 인수 조건 검토는 진행하지 않았습니다. 설치·재현 절차는 [README](README.md), 구조·근거는 [ARCHITECTURE](ARCHITECTURE.md)에 있습니다.
