# PnJ Seoul Planner 구조

## 한 요청의 흐름

React/Vite → 같은 출처의 FastAPI → SQLite 계정 확인 → 현재 조건과 해당 계정의 선호·피드백 수집 → 규칙 기반 코스 생성 → 사용자 선택 → 로컬 JSON 다운로드. 서비스는 루프백에만 바인딩합니다. `plans_api.py`가 호출하는 계산 경계는 `planner.generate(context, mood, trip, history, language)`입니다. SDK, 모델 선택 경로, 비밀 키 판독, 원격 전송 구현은 없습니다.

| 영역 | 주요 파일 | 책임 |
|---|---|---|
| 인증·가입 | `backend/app/accounts.py`, `frontend/src/Auth.jsx` | 가입과 응답·점수·초기 선호를 한 트랜잭션으로 저장. PBKDF2-HMAC-SHA256, 무작위 salt, 만료 시간 8시간의 세션과 해시된 토큰. |
| 검사·선호 | `personality.py`, `data/pnj_facets.json`, `data/preference_rules.json`, `Profile.jsx` | 문항 버전·응답 언어·서버 채점·응답 시각, 사용자 직접 선호와 추정 분리. |

## 검사와 여행 선호

새 회원의 검사 버전은 `pnj-facets-24-v1`입니다. 12특성별로 Johnson의 공개 IPIP 문항 두 개를 선별했습니다. 응답은 5단계 동의 척도입니다. 역문항은 `6 − 응답`, 축 점수는 `(두 채점값의 합 − 2) ÷ 8 × 100`입니다. C6 두 문항은 모두 역방향, O1 두 문항은 모두 정방향입니다. 12축은 각각 독립적입니다. 선별 문항과 한국어 번역은 PnJ 시연용이며, 원척도와 같은 타당성을 검증하지 않았습니다. [공식 IPIP 문항과 채점 방향](https://ipip.ori.org/30FacetNEO-PI-RItems.htm) · [공개 도메인 이용 안내](https://ipip.ori.org/)

초기 추천 가설은 E2→교류, E4→활동, O4→새 경험, O5→배움, C5→계획 구조입니다. 각 0~100점은 `1 + 점수/25`로 1~5 범위로 옮깁니다. O2가 중앙값보다 높으면 미술 활동을 약하게 고려합니다. 직접 확인한 문화·배움 선호가 있으면 O2 추정도 사용하지 않습니다. E3·E1·O3·O1·C6·A3은 프로필에 표시하고 순위에 가중치를 부여하지 않습니다. 미확인 선호는 null입니다. MBTI·국적·성별은 순위에 쓰지 않습니다. 선택한 거주국은 검산된 역사 통계의 집단 선택에만 사용합니다.

기존 `mini-ipip-en-ko-review-1` 응답·점수와 당시 여행 선호를 그대로 읽습니다. 새 24개 응답을 모두 제출했을 때만 이전 검사 원본을 `survey_archive`에 보관하고 새 버전·응답·점수·시각 및 추정 선호를 한 트랜잭션으로 저장합니다. 직접 입력한 선호와 추천 기록은 유지됩니다.

기본 제출은 `POST /api/plans`에 `checkIn`과 언어를 담습니다. `mood.py`가 원문을 메모리에서 해석하고, 저장 가능한 요약과 초기 여행 조건만 다음 단계로 넘깁니다. 한 번의 트랜잭션에서 기분과 추천 결과를 저장합니다. 보완 단계에서는 계정 소유의 `moodId`를 지정하여 그때 사용한 마음과 다시 연결합니다. 기간이 미정이면 인계의 `durationDays`와 미배정 구간의 `day`는 null입니다. 고정 약속이 있다면 날짜·시각은 입력 그대로 보존합니다.

## 추천과 근거

1. 필수 실내·회피 장소·식사 위험·이동 조건을 검토합니다. 고정 약속의 시간 중첩, 다른 장소 간 이동 여유가 0인 약속도 검사합니다.
2. 장소의 활동·환경 특성과 입력을 비교합니다. 정렬은 여행 희망, 현재 확인한 분위기·목표·활동량, 검증용 날씨, 직접 선호, 성격에서 도출한 임시 선호, 실제 이용 기록 순입니다. 같은 우선순위에서 다른 경험과 가까운 권역을 고려합니다. 기분 단어 하나로 새로운 희망을 추정하지 않습니다.
3. 후보들을 열린 날에 배치한 뒤 지정일 정기 휴관, 가용시간, 비용을 재검사합니다. 계획용 체류·휴식 배분과 실제 소요 시간은 별도입니다. 미확인 요금은 null, 확인된 기본 관람료만 소계에 포함합니다. 확인된 부분합만으로 상한을 넘으면 제외합니다. 정보가 부족한 예산·시간·접근성 조건은 보완이 필요한 경험으로 제시하고 해당 사유를 보존합니다.
4. `ranking_rules.json`에서 현재 실험값과 태그 매핑을 확인할 수 있습니다. 매칭 1건 기준 희망 24, 오늘의 선택 9, 날씨 3, 직접 선호 2, 성격 추정 0.4이며 후자의 선호 강도는 중앙값 3과의 거리를 반영합니다. 피드백 2, 과거 노출 0.15도 가설입니다. 서로 다른 우선순위는 단순 가중치 합산으로 뒤집히지 않습니다.
5. SQLite의 `planner_runs`에 사용된 조건·선호·현재 선택·당시 이력 및 제외 사유, `proposals`에 장소별 점수 기여·근거·일정 스냅샷을 저장합니다. 추천 노출, 선택, 거절, 직접 기록한 방문·만족도를 구분합니다. API는 세션 소유자로 조회합니다. 영어·한국어 뷰는 동일한 입력 스냅샷을 사용하고 코스 순서가 일치해야 저장합니다.

## 장소·외부 자료 갱신

`data/places.json`에 기존 서울 장소 33곳을 독립 스냅샷으로 저장했습니다. 사진 30장과 저작자·원본 URL·라이선스·화면용 변경 표기를 함께 유지합니다. 3곳은 사진 미확보이며 출처가 있는 좌표는 21곳입니다. 데이터의 평가 태그와 예상 활동은 기획 분류입니다. 기초 자료 확인일과 방문일의 실제 영업 여부를 구분합니다.

`data/gallery_hours.json`은 서울시립미술관 세 전시관의 정기 운영 정보입니다. 정기 휴관을 날짜별 계산에 적용하고 방문일의 예외사항은 별도로 확인하도록 표시합니다. 담당자는 공식 안내를 확인한 뒤 장소 ID·확인일·근거·버전을 함께 갱신하고 휴관일 테스트를 실행할 수 있습니다. [서소문본관](https://sema.seoul.go.kr/en/visit/seosomun) · [북서울미술관](https://sema.seoul.go.kr/en/visit/bukseoul) · [남서울미술관](https://sema.seoul.go.kr/en/visit/namseoul)

날씨는 매 요청에서 재평가하는 검증용 시나리오이며 실제 예보는 null입니다. 추천기는 서버 전용 2025년 최종 조사 집계를 읽습니다. 개인 신호와 테마 중복을 고려하고 남은 동률에서만 역사적 활동 참여율을 사용합니다. 행사·트렌드는 날짜와 출처를 검사하는 오프라인 연결 경계만 있습니다. [데이터 출처·재생성](DATA_SOURCES.md) · [계산 순서와 비교](ALGORITHM_EVIDENCE.md)

## 미아 인계

`schedule.handoff`는 허용한 필드만 복사합니다. `schemaVersion`, 선택 인스턴스 `planId`, 결정적인 `courseId`, 계획·데이터 버전, 언어·Asia/Seoul, 날짜, 날별 잠금·순서·시간 범위, 좌표, 이동 구간, 식사/비용/이동 조건, 대안, 출처와 확인일, 검증 상태를 포함합니다. 미확인 시각·소요시간·좌표는 null입니다. `draft-demo`와 실제 검증 플래그를 별도로 전달합니다. 비밀번호·세션·검사 답·기분 원문·계정 기본정보는 내보내기 필드에 포함하지 않습니다. 사용자가 직접 적은 장소·약속 설명은 그대로 인계됩니다.

인계 형식 `mia.itinerary/2`에는 당시 검사 버전과 점수, 기분·경험 단서와 기준 시각, 추천·선택 이유, 미확인 조건, 화면 상세도 `detailMode`가 들어갑니다. 원래 저장되지 않았던 검사 스냅샷과 생략한 선택 이유는 null입니다.
