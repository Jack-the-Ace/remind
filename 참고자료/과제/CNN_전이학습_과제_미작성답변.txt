기존 코드에는 제공된 한글 Drive 경로의 NFC/NFD 차이를 처리하는 기능이 없어 경로 탐색을 보완하였다. 또한 폴더명에 제조사명과 차종명이 섞여 있어 원본 클래스는 유지하고 제조사명은 별도 대응 사전으로 표시하도록 하였다. 이는 실제 학습 중 오류가 발생했다는 주장이 아니라 파일과 코드를 검토하여 반영한 수정이다.

기존 코드의 Train/Validation 분리는 유지하되 파일 내용이 같은 복사본이 서로 다른 분할에 들어가는지 점검하도록 보완하였다. Test와 같은 Train 복사본은 학습 후보에서만 제외하고, Train 내부의 같은 파일은 동일 분할로 배정한다. 원본 파일은 변경하거나 삭제하지 않는다. 실제 중복 존재 여부와 처리 건수는 실행 후 출력으로 확인한다.

시간과 학습 부담을 고려하여 수업에서 배운 ResNet152 대신 기존 노트북의 ResNet50을 유지하고, 특징 추출층은 동결한 채 FC층만 학습하도록 하였다. 기본 설정은 배치 16, 5 Epoch이며 GPU를 사용할 수 있으면 활용한다. 검증 손실이 가장 낮은 Epoch를 복원하도록 구성하여 마지막 Epoch만 무조건 사용하는 것을 보완하였다. 다만 이 조치가 정확도를 개선했거나 과적합을 해결했다는 비교 실험 결과는 아직 없다.

과적합은 Train 성능만 좋아지는 동안 Validation Loss가 높아지거나 Validation Accuracy가 낮아지는 흐름 등을 함께 보고 판단한다. Train 지표는 한 Epoch 안에서 가중치를 갱신하며 계산한 값이므로 최종 고정 모델의 Train 성능과 완전히 같지는 않다. 짧은 학습 한 번의 변동만으로 과적합을 확정하지 않는다.

메모리 부족이 실제 발생하면 배치 크기를 8로 낮추고 DataLoader와 모델 설정부터 새로 실행한 뒤 실제 설정을 기록할 수 있다. 학습 지연이 확인되면 Epoch별 시간과 GPU 사용 여부를 근거로 원인을 설명한다. 문제가 없었다면 없었다고 기록한다. 해결 조치를 수행하지 않았다면 수행하지 않았다고 명시한다.

[추가 실험 후보와 실제 수행의 구분]
학습률 조절, 상위 레이어 미세조정, Dropout, 데이터 증강은 기본 실험에서 수행한 개선으로 주장하지 않는다. 시간이 남으면 수업의 layer4 미세조정이나 Train에만 적용하는 증강 등을 선택적으로 비교할 수 있으나, 이 경우 실제 시행한 내용과 Validation 결과를 별도로 기록한다. Test를 반복 확인하면서 설정을 선택하지 않는다.
