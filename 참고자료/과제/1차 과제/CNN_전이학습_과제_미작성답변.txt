자동차 사진은 ImageNet과 같은 일반적인 자연 이미지이므로 사전 학습으로 익힌 윤곽, 질감, 형태 등의 특징을 활용할 수 있다고 생각하였다. 다만 자동차의 세부 차종이나 제조사를 구분하는 과제까지 완전히 같다는 뜻은 아니며, 유사도는 이미지의 성격을 바탕으로 판단한 것이다.

이에 ImageNet 사전 학습 가중치를 불러온 ResNet50의 기존 파라미터를 모두 동결하고, 마지막 FC층을 입력 2,048개·출력 7개의 Linear층으로 교체하였다. 새 FC층만 requires_grad=True로 설정하고 Adam에도 model.fc.parameters()만 전달하였다. 실제 학습 대상 파라미터 수는 14,343개였다.

이 방식은 기존 특징 추출 능력을 활용하면서 학습할 파라미터 수를 줄일 수 있다. 실제 실행 장치도 CPU였으므로 제한된 환경에서 먼저 기본 성능을 확인하기에 적절하다고 판단하였다. 대신 특징 추출부를 자동차 데이터에 맞게 추가 조정하지 않아 세부 차이를 학습하는 데 한계가 있을 수 있다. 전체 재학습이나 일부 합성곱 층의 미세조정과 성능을 비교한 실험은 하지 않았다.

Q3-2. 선택한 전략에 맞춰 PyTorch 또는 TensorFlow/Keras 코드를 작성하고, 모델의 학습(Training) 과정을 수행하시오. (코드 및 학습 로그 첨부)
============================================================

[실제 구현 과정]
PyTorch와 torchvision을 사용하였다. ImageFolder로 Cars/train과 Cars/test를 읽고, transforms.Compose로 Resize((224, 224)), ToTensor(), Normalize를 적용하였다. 정규화의 mean은 [0.485, 0.456, 0.406], std는 [0.229, 0.224, 0.225]이다. Train, Validation, Test 모두 같은 전처리를 사용했으며, 무작위 반전이나 회전 등의 데이터 증강은 적용하지 않았다.

Train 폴더를 Train 2,682장과 Validation 670장으로 나누었다. 모든 DataLoader의 batch_size는 16이며 Train만 shuffle=True로 설정하였다. 모델은 models.resnet50(weights='DEFAULT')로 불러오고 FC층만 학습하였다. 손실함수는 CrossEntropyLoss, 최적화 방법은 Adam, 학습률은 0.001, Epoch는 3회이다. 저장된 실행 출력에서 사용 장치는 cpu로 확인된다.

학습 반복문에서도 model.eval()을 사용하였다. 이는 BatchNorm의 이동 통계가 학습 중 바뀌지 않도록 하는 설정이다. eval() 자체가 역전파를 막지는 않으므로 Train에서는 loss.backward()와 optimizer.step()으로 FC층을 갱신하였다. Validation과 Test에서는 torch.no_grad()를 적용하였다.

[핵심 코드 발췌: 전체 코드는 기존 ipynb에 포함]
transform = transforms.Compose([
    transforms.Resize((224, 224)),
    transforms.ToTensor(),
    transforms.Normalize(
        mean=[0.485, 0.456, 0.406],
        std=[0.229, 0.224, 0.225]
    )
])
dataset = datasets.ImageFolder(root=dataset_path + '/train', transform=transform)
test_dataset = datasets.ImageFolder(root=dataset_path + '/test', transform=transform)
class_names = dataset.classes
train_dataset, val_dataset = random_split(
    dataset, [0.8, 0.2], generator=torch.Generator().manual_seed(42)
)
train_loader = DataLoader(train_dataset, batch_size=16, shuffle=True)
val_loader = DataLoader(val_dataset, batch_size=16, shuffle=False)
test_loader = DataLoader(test_dataset, batch_size=16, shuffle=False)

device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = models.resnet50(weights='DEFAULT')
for param in model.parameters():
    param.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, len(class_names))
for param in model.fc.parameters():
    param.requires_grad = True
model = model.to(device)
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.fc.parameters(), lr=0.001)

epochs = 3
for epoch in range(epochs):
    model.eval()
    epoch_loss = 0
    epoch_accuracy = 0
    for images, labels in train_loader:
        images = images.to(device)
        labels = labels.to(device)
        optimizer.zero_grad()
        outputs = model(images)
        loss = criterion(outputs, labels)
        loss.backward()
        optimizer.step()
        epoch_loss += loss.item() * images.size(0)
        predictions = outputs.argmax(dim=1)
        epoch_accuracy += (predictions == labels).sum().item()

    val_loss = 0
    val_correct = 0
    with torch.no_grad():
        for images, labels in val_loader:
            images = images.to(device)
            labels = labels.to(device)
            outputs = model(images)
            loss = criterion(outputs, labels)
            predictions = outputs.argmax(dim=1)
            val_loss += loss.item() * images.size(0)
            val_correct += (predictions == labels).sum().item()

    print(f'Epoch {epoch + 1}/{epochs} | '
          f'Train Loss: {epoch_loss / len(train_dataset):.4f} | '
          f'Train Accuracy: {100 * epoch_accuracy / len(train_dataset):.2f}% | '
          f'Val Loss: {val_loss / len(val_dataset):.4f} | '
          f'Val Accuracy: {100 * val_correct / len(val_dataset):.2f}%')

[저장된 실제 학습 로그]

Epoch 2/3 | Train Loss: 0.7497 | Train Accuracy: 80.91% | Val Loss: 0.7044 | Val Accuracy: 81.19%
Epoch 3/3 | Train Loss: 0.5636 | Train Accuracy: 87.25% | Val Loss: 0.5984 | Val Accuracy: 84.48%

[결과 분석]
Train Loss는 1.2702에서 0.5636으로, Validation Loss는 0.9394에서 0.5984로 감소하였다. Train Accuracy는 60.89%에서 87.25%로, Validation Accuracy는 71.79%에서 84.48%로 높아졌다. FC층만 학습해도 3 Epoch 동안 분류 성능이 개선되었다.

3 Epoch 중 Validation Loss가 가장 낮은 것은 마지막 Epoch였다. 다만 코드에 최적 Epoch를 따로 선택하거나 복원하는 기능은 없으며, 3 Epoch 학습을 마친 모델을 그대로 Test에 사용하였다. 이후 모델의 state_dict와 class_names를 car-resnet50-class-practice.pth에 저장하고 다시 불러오는 과정까지 수행하였다. 학습 소요 시간은 저장된 로그에 없어 수치로 제시하지 않는다.

Q4-2. 학습 과정에서 발생한 문제점(예: 과적합, 학습 지연 등)과 이를 해결하기 위해 시도한 방법(Learning Rate 조절, Dropout, Augmentation 등)을 작성하시오.
============================================================

[실제 결과에서 관찰한 문제점]
가장 뚜렷한 문제는 클래스별 성능 차이였다. 전체 Test Accuracy는 88.07%였지만 Rolls Royce의 Recall은 0.7027, Hyundai Creta는 0.7313으로 낮았다. 특히 Rolls Royce → Audi 19건의 혼동이 많았다. 데이터 분포도 균등하지 않았지만, 표본이 적은 Mahindra Scorpio의 Recall은 0.9467로 높았으므로 표본 수 차이만으로 오분류 원인을 단정할 수 없다.

과적합 여부는 신중하게 판단하였다. 3 Epoch 동안 Train과 Validation의 Loss가 모두 감소하고 Accuracy가 모두 증가하여, 검증 성능이 나빠지는 뚜렷한 과적합 징후는 관찰되지 않았다. 마지막 Train Accuracy 87.25%와 Validation Accuracy 84.48%의 차이는 2.77%p였다. 다만 3 Epoch의 짧은 기록만으로 과적합이 전혀 없다고 확정할 수는 없다. Train 지표는 Epoch 안에서 가중치가 갱신되는 동안 집계되고 Validation은 해당 Epoch 학습 후 계산되므로 두 수치를 완전히 같은 조건으로 볼 수도 없다.

실행 장치는 CPU였지만 Epoch별 소요 시간이 저장되어 있지 않아 학습 지연의 정도는 확인할 수 없다. 저장된 출력에는 메모리 부족이나 학습 중단 오류가 기록되어 있지 않다.

[실제로 적용한 설정과 조치]
ImageNet 사전 학습 ResNet50의 특징 추출부를 동결하고 FC층 14,343개 파라미터만 학습하였다. 학습 중 model.eval()을 사용해 BatchNorm의 이동 통계를 고정했고, Validation과 Test에서는 torch.no_grad()를 사용하였다. 이는 적은 데이터와 실행 환경을 고려해 처음부터 적용한 설정이다. 문제 발생 전후를 비교하여 효과를 검증한 개선 실험은 아니다.

학습률은 0.001로 고정하였고, 학습률 조절, Dropout 추가, 데이터 증강, 클래스 가중치 적용, 일부 합성곱 층의 미세조정 등은 수행하지 않았다. 따라서 이러한 방법으로 과적합이나 오분류를 해결했다고 쓰기는 어렵다. 이번 과제에서는 FC층만 학습하는 기본 실험과 결과 확인까지 수행했으며, 성능 개선을 위한 비교 실험은 부족하다.

[한계와 앞으로의 개선 방향: 아직 수행하지 않은 제안]
우선 Rolls Royce → Audi 등 실제 오분류 이미지를 확인하여 차체 특징, 배경, 촬영 각도와 이미지 품질에 어떤 공통점이 있는지 살펴볼 필요가 있다. 또한 학습·검증·테스트 사이의 중복 이미지 여부를 별도로 검사하지 않았으므로, 중복이 없다고 단정할 수 없다. 현재 random_split은 클래스 비율을 보장하지 않아 분할 후 클래스 분포 확인도 필요하다.

추가 실험에서는 Train에만 무작위 반전이나 적절한 크롭 등의 증강을 적용하거나, ResNet50의 마지막 블록을 작은 학습률로 미세조정하는 방법을 비교할 수 있다. 클래스 불균형을 고려한 가중치 적용도 후보가 될 수 있다. 다만 이런 방법의 효과는 실제 실험 전에는 알 수 없다. 같은 검증 조건에서 한 번에 한 설정을 바꾸고 Validation Loss와 클래스별 지표를 비교한 뒤, 선택한 설정을 Test로 최종 평가하는 것이 좋겠다.
