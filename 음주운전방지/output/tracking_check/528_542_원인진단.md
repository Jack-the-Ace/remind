# 528~542프레임 원인 재현

현재 track_preview.py와 yolo26n.pt, conf=0.1, 기본 ByteTrack 설정을 바꾸지 않았다. 진단 스크립트가 현재 main()을 호출해 첫 프레임에서 (690,560)을 한 번 선택한 뒤 676프레임 전체를 처리했다. 추적 전 YOLO 결과는 on_predict_postprocess_end 콜백을 추적 콜백 앞에 넣어 복사했다. 따라서 model.track의 최종 result.boxes를 YOLO 검출 원본으로 간주하지 않았다. Target.update()는 현재 소스를 읽고 분기 안에 기록문만 추가해 실행했다. 최종 선택 로그는 이전 final.json과 완전히 같았다. 화면 대신 실제 프레임 합성 이미지를 확인했다. 운영 스크립트·설정은 수정하지 않았다.

## 531프레임 확인

원본과 전후 프레임을 비교하면 상자 중심은 오른쪽으로 이동하는 은색 승용차다. 좌표는 약 [898,502,1136,640]. 상자 왼쪽에 검은 SUV와 불빛 일부가 함께 들어 있어 타깃만 깨끗하게 분리된 상자는 아니다. 검은 SUV만을 감싼 상자로 보기는 어렵다. 모델의 정밀한 객체 분리 의도는 확인 불가이며, 육안 판정은 '은색 차를 포함한 겹침 상자'이다. 현 코드는 이 상자를 외형 비교하기 전에 ID 없음으로 건너뛴다.

## 처음 놓친 원인과 복귀하지 못한 원인

처음 놓친 프레임은 529. YOLO는 은색 차 상자를 검출했으므로 처음부터 탐지에 실패한 것이 아니다. ByteTrack 연결/확인 단계에서 ID가 유지되지 않았고 선택 코드에 넘어온 후보가 비어 있었다. 529~530에 생기는 임시 트랙이 추적 후처리에서 감춰지는 구현이 있으며, 531은 추적 결과 없이 검출 상자만 남는다. 정확히 어떤 거리 비용 때문에 기존 17에 연결되지 않았는지는 이번 로그만으로 단정하지 않는다. 535~540은 별도로 YOLO 탐지 누락도 겹친다.

542에서 ID 58은 은색 차이다. 마지막 채택은 528, 경과 14프레임. 위치·크기 검사는 통과했다. 외형 점수 0.068879 < 기준 0.20, 색상 점수 0.493637 < 기준 0.70으로 둘 다 실패했다. 이 프레임에서는 후보 간 모호성 검사나 새 ID 3프레임 확인 단계까지 가지 않았다. 543~558에는 은색 차 후보 58이 위치·크기 조건에서 탈락한다. 예: 543 거리 1.287 > 허용 1.25, 558 거리 2.441 > 허용 1.4. 기억한 위치가 계속 528에 머물러 있어 옆 차선으로 이동한 차량과 멀어진다.

559 /18.600초: 마지막 채택 528에서 31프레임이 경과해 처음으로 '30프레임 초과'가 실행됐다. 은색 차에 ID 58이 있어도 이후 위치나 외형을 검사하지 않는다. 따라서 30프레임 제한은 529의 최초 누락 원인이 아니라, 복귀를 완전히 막는 후속 원인이다.

## 다음에 바꿔볼 한 가지

새 ID 후보를 마지막 한 장의 외형과 비교하는 방식을, 최근 정상 추적된 여러 장의 외형과 비교하는 방식으로 바꿔 시험한다. 이번 542의 첫 직접 탈락 조건을 겨냥한다. 위치 제한·3프레임 확인·30프레임 제한은 그대로 두고, SUV로 잘못 연결되는지와 542에서 복귀하는지를 먼저 비교한다. 단순 기준 완화로 성공을 가정하지 않으며 이 변경 하나로 이후 위치 조건 문제까지 해결된다고 보장하지 않는다. 이번에는 수정하지 않았다.
