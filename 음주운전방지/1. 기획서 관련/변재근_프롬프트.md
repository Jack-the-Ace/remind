- 작성자 변재근
- 개발 목표 : 2026년 11월 30일까지 로컬 PC에서 동작하는 컴퓨터 비전 웹앱 제작


 1. 내가 만들고 싶은 서비스

나는 위험한 주행을 목격한 사람이 상대 차량을 뒤쫓지 않고도, 이미 확보한 블랙박스·도로 영상에서 확인할 장면을 빠르게 찾도록 돕고 싶어. 예를 들어 자가용으로 출퇴근하는 30대 직장인이 위험해 보이는 운전을 목격해도, 긴 영상을 다시 돌려보며 같은 차를 찾고 발생 시각을 적기에는 시간이 부족해. 그래서 "영상 속 차량을 한 번 지정하면, 프로그램이 그 차를 계속 따라가면서 위험 의심 행동의 종류·횟수·발생 시각과 근거 장면을 정리"해 줬으면 해.

텍스트 입력만으로는 여러 차량 중 같은 차를 계속 찾거나 차선과의 위치 관계를 확인하기 어려워. AI로 영상 속 차량과 차선을 찾고, 프로그램에서 두 위치가 시간에 따라 어떻게 바뀌는지를 계산해 줘. 결과 화면에서는 사용자가 해당 장면을 직접 다시 볼 수 있어야 해.


 2. 11월에 꼭 완성할 것

1. 로컬 웹에서 도로 주행 영상을 올리고, 영상 속 차량 한 대를 사용자가 직접 선택하게 해 줘.
2. 선택한 차량을 영상 속에서 계속 추적하고, 따라가는 차량만 네모 상자로 눈에 띄게 표시해 줘. 차량이 가려지거나 화면 밖으로 사라지면 상태를 알려 주고, 다른 차로 바뀌었을 가능성이 있으면 집계를 보류해 줘. 필요하면 사용자가 다시 선택할 수 있게 해 줘.
3. 실제 추가 학습한 차선 모델을 영상에 적용해 줘. 차량과 차선의 위치 변화를 이용해 "차선 기반 위험 의심 행동을 최소 한 종류 자동 탐지하고 카운팅"하는 게 이번 프로젝트의 핵심이야. 첫 후보는 "차량이 차선 경계를 넘어간 의심 구간"으로 잡아 줘. 경계를 연속으로 넘고 있는 장면은 한 건으로 기록하고, 연속 프레임마다 횟수가 올라가지 않게 해 줘. 사건 시작·종료 및 재집계 조건은 짧게 설명하고 설정값으로 남겨 줘.
4. 결과에 행동 종류, 횟수, 발생 시각이나 시작·종료 구간을 표시해 줘. 목록을 누르면 해당 장면을 다시 확인할 수 있게 하고, 분석 결과와 근거 영상 위치를 로컬에 저장해 줘.
5. 차선이 흐리거나 끊겨 보이는 경우, 야간·역광, 차량 가림이나 추적 상실 등은 화면에 `판단 보류` 또는 `추적 상실`로 표시해 줘. 차선 경계를 넘는 행동에는 정상 차로 변경도 포함될 수 있으니, 결과 이름은 `차선 경계 이탈 의심`처럼 쓰고 사람이 영상으로 확인하게 해 줘.

이번에는 "한 PC에서 영상 입력부터 결과 확인·저장까지" 연결하는 데 집중해 줘. 차종·색상·번호판 인식, 실시간 모바일 녹화, 음성 신고, 생활형 신고는 확장 항목으로 남겨 줘. 12월 최종프로젝트에서는 PC1이 차량 정보와 분석 기록을 보내고 PC2가 전달 정보만으로 같은 차량을 다시 지정해 추적·집계를 이어가는 흐름을 생각하고 있어. 같은 영상으로 시연할 경우에는 같은 차량을 다시 찾는지 확인하고, 재생별 집계는 구분해 줘. 실제 관제실·경찰 연동은 장기 구상으로 남겨 줘.


 3. 실행 환경과 기술 스택

- 실행 방식 — 한 대의 Windows PC에서 브라우저와 Python 서버를 실행해 줘. React 화면은 업로드·차량 선택·결과 표시를 담당하고, 모델 추론과 영상 처리는 로컬 FastAPI 서버에서 실행해 줘.
- 화면과 API — React + Vite로 화면을 만들고, FastAPI에서 영상 분석 요청을 받고 처리 상태와 결과를 전달해 줘.
- 비전 처리 — 수업에서 배운 Python, PyTorch, OpenCV, Ultralytics YOLO를 우선 사용해 줘. 사전 학습 YOLO로 프레임별 차량 위치를 찾고, ByteTrack으로 같은 차량을 이어 줘. 차선은 DeepLabV3-MobileNetV3를 차선 데이터로 추가 학습해 표시해 줘. OpenCV로 영상 읽기, 상자 표시, 차선과 차량의 상대 위치 계산, 결과 영상 저장에 필요한 처리를 해 줘.
- 저장 — 분석 기록과 영상 경로는 SQLite에 보관하고, 사건 종류·횟수·시각 등은 JSON·CSV로 내보낼 수 있게 해 줘. 원본과 결과 영상은 로컬 파일로 관리해 줘.
- 버전과 설치 — 작업 시작 전에 Python·Node.js와 설치된 패키지 버전, GPU 사용 가능 여부를 확인해 줘. 수업 코드와 현재 환경에서 호환되는 버전을 선택하고, 실제로 사용한 버전과 실행 명령은 의존성 파일과 README에 기록해 줘.

글은 쉬운 말로 쓰고, 영상과 중요한 숫자가 먼저 보이도록 해 줘. 가려짐이나 판단 보류는 색과 짧은 문구를 같이 써서 상태를 알아볼 수 있게 해 줘.


 5. 데이터와 검증 방법

- AI Hub, BDD100K, KITTI Tracking, CULane과 사용 허가를 확보한 도로 영상을 후보로 살펴봐 줘. 자료별 이용 조건과 라벨을 확인한 뒤 차선 학습용과 차량 추적 검증용으로 구분해 줘. 원본 영상이 같은 프레임은 한 묶음으로 두고 학습·검증·시험을 8:1:1로 나눠 줘.
- 차선 위치가 라벨로 제공되면 차선과 배경을 구분하는 마스크로 변환해 줘. 직접 라벨링할 때는 CVAT를 우선 검토하고, 잘린 차선·흐린 차선 등 표시 기준을 일관되게 적용해 줘. 영상 품질과 라벨 누락 여부도 확인해 줘. 초기 확보 목표는 1,000장 이상이고, 추가 학습은 30~40에포크(반복 학습)을 계획하되 실제 설정과 결과를 기록해 줘.
- 학습에 쓰지 않은 영상에서 사람이 적은 사건 종류·횟수·시각과 자동 집계 결과를 비교해 줘. 오탐, 누락, 중복 집계와 추적이 끊긴 구간을 따로 기록해 줘. 추적 유지율 90% 이상, 차선 위치 일치도 IoU 0.50 이상은 기획 단계의 초기 목표야. 실제 평가할 때에는 각 지표를 어떻게 계산했는지도 남겨 줘.
- 같은 영상의 수동 검토 시간과 RedBox를 사용한 검토 시간을 실제로 재서 비교해 줘. 기획서의 10분 → 5분은 설명용 가정과 검증 전 목표이므로, 개발 후 측정값과 구분해 줘.


 6. 개발 예정 순서와 첫 작업

1. 11.12–16 기획과 개발 환경 확인
2. 11.17–20 영상 입력, 차량 검출·선택과 추적 구현
3. 11.21–24 차선 데이터 준비, 모델 추가 학습과 적용
4. 11.25–27 차선 기반 의심 행동 최소 한 종류 집계와 근거 저장 연결
5. 11.28–30 새 영상으로 시험하고, 사람의 확인 결과와 비교해 한계와 시연 정리

먼저 현재 작업 폴더와 실행 환경을 살펴보고 내가 실습한 YOLO 영상 객체 탐지, OpenCV 영상 입출력과 PyTorch 학습 코드 중 재사용할 부분을 알려 줘. `zz_숫자`로 된 연습 파일과 `재근메모`·`메모`·`aaa` 엑셀·텍스트 파일은 검토 대상에서 빼 줘. 기존 실습 파일과 기획서는 참고만 하고, 새 프로젝트 폴더 안에서만 개발해 줘.

첫 작업에서는 "영상 업로드 → 실제 YOLO 차량 검출 → 차량 한 대 선택 → ByteTrack 추적 → 화면에서 확인"까지 한 번 연결해 줘. 간단한 폴더 구조와 구현 순서를 알려 준 다음, 실제 실행 파일을 만들어 줘. 이 단계의 완료 조건은 한 영상에서 지정한 차량을 따라가는 상자를 확인하는 거야. 이후 차선 모델을 학습하고 연결한 뒤, 자동 집계와 저장까지 확인해야 11월 MVP가 완료돼.

수업에서 배운 코드 흐름을 최대한 살려서 내가 읽고 수정할 수 있게 만들어 줘. 마무리할 때에는 실행 방법과 확인한 결과, 남은 문제를 쉬운 말로 정리해 줘. 실측하지 않은 수치나 아직 연결하지 못한 기능은 현재 상태를 그대로 알려 줘.
