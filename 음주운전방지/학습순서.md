# RedBox 받아쓰기 순서

처음에는 001에서 JPG 한 장에 네모를 그린 뒤 002에서 영상에 ID를 붙이고 006에서 한 차를 선택하세요. 003~005와 007~013은 추적이 끊긴 이유를 더 알아보는 실습입니다. 014부터 라벨의 뜻을 확인하고, 024부터 차선 모델을 만들어 034에서 사건 후보를 기록합니다. 사건 화면을 열려면 035를 실행하세요.

## RedBox 개발 원칙

사용자가 기록할 차량과 행동을 고르고, RedBox는 추적·OCR·이벤트·영상으로 검토를 돕습니다. 최종 판단은 사람이 합니다. 로컬 시연과 근거에는 원본 번호판과 얼굴, 실제 OCR 문자열을 유지합니다. 이벤트 JSON에는 자동 감지 결과와 사람이 지정한 시연 이벤트의 출처를 기록합니다.

## 순서를 정한 근거

- Git에서 소스가 처음 추가된 커밋은 11월 18일의 `1bd3ae7e`·`e6379fdb`, 11월 19일의 `2b127af9`입니다. 여러 파일이 한 커밋에 들어 있어 커밋만으로 분 단위 순서를 알 수 없습니다.
- 같은 커밋 안에서는 추적 검증결과, 628·197 점검 기록, 이동 계획, 학습 로그, 영상 관찰 기록을 파일 생성 시각과 대조했습니다. 002는 당시 코드를 보관한 파일이므로 선택 기능이 있는 006보다 앞에 놓았습니다. 006과 007은 정리 전 코드에서 기본 입력 영상 이름만 달랐습니다.
- 세 화면 파일은 생성 시각이 같습니다. 화면을 제공하는 서버 → HTML 구조 → CSS 배치 → JavaScript 동작 → 브라우저 검증 순서로 공부하도록 정했습니다.
- 현재 목록에는 Python 소스 37개와 웹 소스 3개가 있습니다. 프로젝트에 `.ipynb`나 `(1)` 사본은 없었습니다. 진단기가 생성한 `diagnostic_update.py`와 `buffer90.yaml`, 컴파일 캐시, 외부 라이브러리, 과거에 삭제된 기획서 생성 도구는 제외했습니다.
- 다음 새 작업은 **071**입니다. 기존 번호는 유지합니다. 번호가 표에만 있는 파일은 다른 실습에서 일반 Python import로 불러옵니다.
